# Next-version development state

Start in the existing agent with `$skip implement this`. Windows Codex is the first easy-install target; Linux and Paseo use the same Core. This page describes development source, not the currently published installation.

Activation binds the external project and can record measured NOW facts without generating goals, specifications or approvals. New session goals require an actual current user request. Goal and change risk are evaluated separately against current scope/source/policy. Reversible low-impact work can use the v2 compact request gate; material work keeps the existing v1 artifact gates. Uncertainty requires investigation. All enforcement remains advisory.

The Codex adapter checks the current local host session's actual user message. The Paseo panel keeps native requests in server memory and runs the same Core in the selected daemon's workspace. Agent assessments cannot replace the original native request. Results preserve evidence surfaces, gaps and current-source checks; verified facts can be written to NOW using revision CAS.

The Windows package bundles pinned CPython, licenses, an isolated module path and file hashes. It does not require end users to install Python, Git, npm or WSL. The existing source/skill installation remains a common fallback.

Windows app installation, session-record availability and the complete first-use journey still need native acceptance. Linux server integration tests do not replace Paseo visual/live-install acceptance. Adding Windows CI does not mean that workflow has run. The Codex operation recognizer is conservative for explicit Korean/English requests; a bare “yes” does not invent implementation scope. Public catalog placement, upload and installation are separate from this source implementation.
